## Architecture

**"On va où ?"** is a Nuxt 4 / Vue 3 app that helps users find travel destinations based on weather tolerance. All source code lives under `app/` (Nuxt 4 convention).

### Data flow

1. `public/data.json` — static dataset of cities with 2-week weather forecasts (WMO codes + temperatures). This is the only data source; there is no external API call.
2. `server/api/weather.get.ts` — Nuxt server route that reads and returns `data.json`. Called once on mount via `$fetch('/api/weather')`.
3. `app/stores/weather.ts` — Pinia store (Composition API style) that holds all app state. Key actions:
   - `formatData()` — transforms raw `CityWeather[]` into `CityProposition[]` for display
   - `applyTolerance()` — filters cities by bad-weather days within the selected date range; sets `isSubmitted`, `startIndex`, `endIndex`
   - `resetPropositions()` — restores the full city list

### Component tree

```
layouts/default.vue          # Sidebar (desktop) + Drawer (mobile) shell
  FilterPanel.vue            # Date pickers + tolerance slider + submit button
pages/index.vue
  ResultsPanel.vue           # Search/sort bar + city grid; fetches data on mount
    CityCard.vue             # Individual city card; reads store.startIndex/endIndex
                             # to slice the correct date range after submit
```

### Key design decisions

- **`isSubmitted` flag** gates display logic: before submit, `CityCard` shows a week selector (semaine 1 or 2); after submit, it slices the exact date range using `startIndex`/`endIndex` across the concatenated `semaine1 + semaine2` arrays.
- **Bad weather codes** (`BAD_WEATHER_CODES` in the store) are WMO codes for rain, storms, and snow. Cities exceeding `toleranceDays` bad days in range are removed from `propositions`.
- **Minimum trip duration** is 3 days — enforced in `getEndIndex()` by starting the search from `fromIndex + 3`.
- **Theming** uses custom CSS variables (`--color-bg`, `--color-surface`, `--color-accent`, etc.) defined in `app/assets/css/tailwind.css`, applied inline via `style` attributes throughout components. shadcn-nuxt components coexist but use their own Tailwind token layer.
- **Weather icons** map WMO codes to Font Awesome 5 class names via `app/utils/weatherIcons.ts`. Font Awesome is loaded from CDN.
- **UI components** (`app/components/ui/`) are shadcn-nuxt components — edit with care, they may be regenerated by `npx shadcn-vue add`.
- **Distance sorting** uses the Haversine formula in `ResultsPanel.vue` and requires the browser's Geolocation API; distance is stored on `CityProposition.distance` (optional field).
